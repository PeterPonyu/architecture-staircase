# Train the pathway, deposit the computation: a two-probe dissociation of component ownership in transformer emergence

Project page: https://peterponyu.github.io/architecture-staircase/

## Title

Train the pathway, deposit the computation: a two-probe dissociation of component ownership in transformer emergence

## Description

This repository holds freeze and ablation probes on an architecture-shaped
degree staircase, plus the committed per-run logs. Freeze probes ask which
sub-network must be trained. Mean-ablation probes ask where the trained
computation sits. Site modules: Probes, Staircase, Scale, Subspace, Ledger,
Rebuild.

Repository: https://github.com/PeterPonyu/architecture-staircase

## Dataset Information

All primary tasks are synthetic. Boolean degree-staircase targets and
in-context induction streams are generated by the committed runners. Those
generators are the data source.

Recorded outputs live under `experiments/results/` as JSON / JSONL logs.

## Code Information

- `experiments/<study>/` — runner and analysis code per sub-experiment
- `experiments/arch_staircase/` — scale-grid and freeze-ownership audit

- `experiments/results/` — committed per-run logs
- `experiments/grokking/` — shared trainer pieces used by the probes

## Methodology

On Boolean degree-staircase targets (~400k-parameter transformers), freeze
probes measure training necessity across AdamW / Muon / SGDM (SGDM fit-gated).
Trained mean-ablation is run under AdamW and Muon. Geometry uses the
staircase index (SI) with a two-one-sided equivalence test at the pre-specified
bound, plus depth/width checks, a 24-configuration scale grid, and a principal
component analysis (PCA) subspace audit. One-sample tests versus SI=1 are
robustness checks only.

Steps for implementation:

1. Clone this repository or download the Zenodo v1.5.4 pack.
2. Install Python 3.11+, PyTorch, and numpy.
3. Read committed logs under `experiments/results/` for recorded outputs.
4. Rerun `python experiments/<study>/run_*.py` only when you need new cells.
5. Rebuild the project page from `portal/` only if you changed portal source.
